# safe-wording-guard（小红书安全用词守卫）

## 一、问题背景

小红书对"为其他平台/官方渠道导流"的内容会限流、降权甚至删除。常见的踩点：

| 类别 | 敏感词（出现即高危） |
|---|---|
| 官方渠道点名 | 官方 H5、官方小程序、官方 App、官方公众号、官方报名、官方通道、官方入口 |
| 第三方平台点名 | 微信、公众号（直接点名）、支付宝小程序、抖音、B 站、知乎 |
| 链接/二维码 | 直接放 URL（即使是官网）、放二维码图片、"扫码"、"添加联系方式" |
| 拉新转化词 | 报名、预约、注册、下载、登录、扫码进群、加好友、领优惠、限时领取 |
| 自夸数据 | "报名已突破 X 万"、"售罄"、"全网销量第一"、"现象级刷屏"（未认证时） |

> **经验法则**：任何可能被算法解读为"让用户离开小红书去另一个平台"的表达都要避开。

## 二、平台硬限制（最容易漏、后果最隐蔽）

| 项 | 上限 | 超限时的表现 |
|---|---|---|
| **标题** | **20 字** | ⚠️ **静默失败**：不报错、发布按钮仍可点、`submit-disabled=false`、无无效字段提示，但点了完全不发请求。只有编辑器内部 toast「标题最多输入20字哦~」一闪而过 |
| 正文 | 1000 字 | 提交时被明确拒绝 |

**为什么这条最危险**：它不产生任何可捕获的错误。发布脚本会看到 `FILL_STATUS: READY_TO_PUBLISH` 一切正常，点下去却什么都没发生，很容易误判成"脚本坏了/被风控了/要多开标签页"，从而在错误的方向上排查很久。

**实测证据**（2026-09-06）：

| 标题 | 字数 | 结果 |
|---|---|---|
| 外滩夜色｜黄浦江畔的傍晚 | 12 | ✅ 发布成功 |
| 广州深圳两场AI活动本周同期举办 | 16 | ✅ 发布成功 |
| 9月9日杭州深圳两场AI展会同期开幕 | 18 | ✅ 发布成功 |
| 9月11日广州：中国—东盟AI+制造合作交流会议 | 24 | ❌ 静默失败（连续 3 次） |

> **注意**：早期笔记里记的"标题 ≤38 字"是**错的**，实际是 20 字。写稿时按 18 字以内留余量。

## 三、安全替代说法（按场景）

### 1. 报名 / 参会 / 入场

❌ 官方 H5 报名 / 扫码 / 官方小程序报名
✅ 看评论区置顶 / 留意官方账号近期推文 / 具体报名方式可关注官方账号 / 凭大会身份入场

### 2. 时间地点信息

❌ 链接：https://www.inclusionconf.com/
✅ 地点：上海市黄浦区局门路 689 号黄浦世博园区 / 9 月 9 日—12 日

### 3. 账号名 / 公众号名

❌ 关注公众号「Inclusion 外滩大会」
✅ 关注主办方账号 / 留意主办方近期推文

### 4. 想突出"很热门"

❌ 报名已突破 5 万 / 现象级 / 刷屏
✅ 吸引了大量关注 / 报名反响热烈 / 创下历届规模新高

### 5. 想说"免费/优惠"

❌ 免费报名 / 0 元抢票 / 限时优惠
✅ 观众免费开放 / 对公众开放 / 入场免费

### 6. 给"研究成果"标来源（易漏：写了域名就等于放了网址）

"要做就做透 + 附来源"是本项目的硬要求，但**附来源 ≠ 贴网址**。
读者只要能顺着文本找到站外，算法就可能判站外导流——所以来源只能写
**机构名 + 项目名 + 论文编号**，不能出现域名。

| ❌ 会命中 P0 | ✅ 安全写法 |
|---|---|
| 开源地址：github.com/google/mantis | 谷歌开源的 Mantis 项目已公开 |
| 代码见 github.com/FinStep-AI/Alpha-R1 | 该团队在开源社区放出了 Alpha-R1 |
| 详见 arxiv.org/abs/2608.23189 | 论文编号 arXiv 2608.23189 已公开 |
| 官网：https://www.xxx.com/ | 由主办方公布的大会信息页（**只写名称，不写网址**） |
| 报名入口：官方 H5 | 按大会公布的登记渠道实名登记 |

**判定口径**：不看"有没有 `http://`"，只看**文本里有没有可识别的域名**。
裸域名（`github.com/...`、`xxx.ai`、`www.xxx.com`）与完整 URL 同罪。
`arXiv 2608.23189` 这类**纯编号**不含域名，安全。

#### ⚠️ 组合判定：说"免费"又写"参与方式"会命中 P1（2026-09-10 实测）

写活动/展会稿时，往往既要说"要登记"、又要说"不花钱"，这两件事撞在一起就会被判拉新：

> 命中规则：**报名/预约/注册 + 免费/限时** 同现 → P1 告警
> 原句：「门票**免费**，但需在线实名**登记**并通过审核」

**即使按上面第 5 条改写成"观众免费开放/入场免费"，只要同段出现"登记/报名/预约"，仍会命中。**
活动稿必须写参与方式（见 `writing-facts-only` 第 5 条），所以要把"免费"这一侧换掉：

| ❌ 会命中 | ✅ 安全写法 |
|---|---|
| 门票免费，需在线登记 | 需在线登记取得观展凭证（**不收费**） |
| 免费票，登记后领取 | 登记后获取电子票（**不收费**） |
| 限时免费报名 | 提前**登记**可**免** 50 元现场门票 |

要点：保留"登记/报名/预约"（信息必写），把"免费/0元/限时"换成 **不收费 / 无需购票 / 可免 XX 元**。
改完必须重跑 `check_wording.py` 确认退出码为 0。

## 四、预检脚本

`helpers/check_wording.py` —— 发布前对 title + content 跑一遍，命中关键词直接给出告警和改写建议。

### 用法

```bash
# 标题 + 正文一起查（推荐，会同时校验 20 字 / 1000 字上限）
python helpers/check_wording.py --title "标题文本" --file path/to/content.txt

# 只查正文
python helpers/check_wording.py --file path/to/content.txt

# 或从 stdin
cat path/to/content.txt | python helpers/check_wording.py
```

退出码：
- `0` 全部安全
- `1` 命中 P0（高危）
- `2` 命中 P1（中危，可调整）

> **⚠️ 传正文一律用 `--file`，不要用 `--content` 传路径。**
> `--content` 收的是**文本本身**；把 `xhs_publish/xx_content.txt` 这种路径传进去，
> 脚本只会去检查那串路径字符，永远返回"安全"。2026-09-11 就是这样让含「扫码」
> 的稿子通过预检并发布的。现在脚本内置防呆：`--content` 若收到存在的文件路径，
> 会打印 `[warn]` 并按文件内容读取——但**不要依赖防呆，写命令时就该用 `--file`**。

### 检查项

P0（必须改）：
- **标题超过 20 字**（静默失败，见第二节）
- **正文超过 1000 字**
- 直接放 URL（http/https）
- **出现站外域名**（裸域名同罪）：`github.com/xxx`、`autoclaw.z.ai/blog/...`、
  `www.xxx.com`、`xxx.com/cn/org/net/io/ai/dev/...` —— **正文一律不写网址**
- "扫码"、"添加好友"、"加群"
- "官方 H5"、"官方小程序"、"官方公众号"、"官方 App"、"官方报名"
- 直接点名第三方平台："微信"、"支付宝小程序"、"抖音"、"B 站"

P1（建议改）：
- "报名"、"预约"、"注册"、"下载" —— 单独出现风险不大，但和"免费 / 0 元 / 限时"组合时高危
- 自夸数据类："突破 X 万"、"刷屏"、"现象级"、"售罄"

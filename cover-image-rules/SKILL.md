# cover-image-rules

> Patch：把"封面配图规范"从主 skill 抽出，独立维护。
> 适用范围：red-book-skills 任何发图场景（图文 / 视频封面 / 配图）。

## 加载方式

主 skill 顶部 `Loaded patches` 段会引用本 patch。本 patch 本身可以被 `Skill` 工具直接加载（不依赖主 skill 的代码）。

## 规则

### 允许直接使用「官方宣传图」

- 主办方 / 组委会 / 官方机构 / 官方媒体发布的宣传图、通稿配图、现场图、场馆图。
- 截图前要去除杂志/视频的水印；保留来源标识更佳。
- 民间号二次剪辑、自媒体改图、内容农场图不用。

### 禁止出现「具体人物」（硬性红线）

| 类别 | 是否允许 |
| --- | --- |
| 嘉宾 / 演讲者 / 主持 / 受访者 | ❌ |
| **宣传大使 / 形象大使 / 代言人** | ❌（即便官方授权） |
| 观众特写、可指认剪影或背影 | ❌ |
| 图文呼应造成的指认（图含人 + 正文点名） | ❌ |
| 远景人群，人脸不可辨、无独立主体 | ✅ |

判定：能看出"这是某个人"就不合格。**官方身份不是豁免条件。**

### 构图优先级

发布到公开平台的封面，按以下优先级选图：

1. **城市地标 / 建筑外景**（首选）
2. **风景与天际线**
3. **场馆与展区环境**
4. **器物 / 装置 / 展品特写**
5. **抽象信息图**（仅在以上都不可得时退用）

### 官方图含人物时的处理顺序

1. 换图（同主题无人物版）
2. 裁切（保留地标/风景主体，画面完整不产生歧义）
3. 改生成为地标风景示意图

不再"作废重做"作为首选——能用现成图就优先用现成图。

### AI 生成图的红线

提示词必须显式禁止以下要素（涉及公开内容合规）：

- 任何地图、海岸线、地理边界、国界轮廓、省份轮廓、行政区划
- 任何文字、字母、数字、地名
- 真实人物肖像、明星、网红
- 旗帜、国徽、政治符号
- 车辆、证件、票据
- **完整的人形机器人照片（恐怖谷效应，会引发不适，2026-09-11 用户明确要求）**
  - 允许的替代：展馆外景 / 会议现场 / 数据中心机房 / 芯片与电路 / 机械臂局部 / 工业机器人局部 / 观众席 / 抽象机器人轮廓（无面部细节）
- **二维码、条形码、票券凭据**

### 风格要求：真实感优先（2026-09-10 修订）

活动 / 展会 / 场馆 / 设备类内容，封面一律优先 **真实感照片风格（photorealistic）**，不要用简单几何图形、色块拼接的"抽象示意"。

1. 首选 photorealistic：建筑外景、场馆内景、展区环境、展品与设备特写、数据中心 / 机房等真实质感画面
2. **参考主办方物料确定"该拍什么"**——场馆外观、展区布置、核心展品、城市地标，按这个清单写生图提示词
3. 但不直接搬运**含二维码、含水印、含可识别人物**的官方物料图（官方图可用的前提见上一节）
4. 抽象信息图仅在既拿不到实拍、也生不出真实感图时退用

反面案例：用几个圆、几条线拼成的抽象示意图当活动封面——信息量为零、观感差，不再使用。

生图提示词模板（在原有红线基础上追加）：

```
Photorealistic [architectural / event / product] photography of <主体>,
<光线与氛围>, wide angle, high detail, professional.
STRICTLY NO text, NO letters, NO numbers, NO logos, NO QR codes,
NO people, NO faces, NO vehicles, NO maps.
```

#### 生图踩坑：文件名前缀冲突会导致图片被覆盖（2026-09-10）

生图工具按**提示词前若干字符 + 时间戳**生成文件名。一次并行生多张图时，若提示词开头相同（例如都以
`Photorealistic photograph of a ...` 起头）且落在同一秒，**后生成的会覆盖先生成的**，最终只拿到一张。

应对：

1. 并行生多张图时，**每张的提示词开头必须不同**（换主语或换首词，如
   `Realistic architectural photo of ...` / `Realistic event photography of ...`）
2. 生完后**逐张核对文件数量与文件时间**，缺哪张补哪张，不要默认"调用成功=文件在"
3. 命名固定用 `<用途>_<序号>.png` 保存到稿件目录，避免后续引用错图

### AI 声明规则

- 任意配图为 AI 生成 → 启用内容声明：发布命令传 `--content-declaration`
- 全为官方实拍 + 正文非 AI 撰写 → 可省略声明
- 混用（部分实拍 + 部分 AI）→ 当作"含 AI"处理

## 验收清单（每次发图前过一遍）

- [ ] 图源是否清晰可信（官方/原创/已授权）？
- [ ] 是否含可识别自然人（含大使）？
- [ ] 是否含地图 / 海岸线 / 国界？
- [ ] 是否含文字 / 数字 / 旗帜？
- [ ] 图和主题是否对得上（展会就用场馆/展品，活动就用现场/地标）？
- [ ] 是否含二维码 / 条形码 / 票券？
- [ ] 是否需要 AI 声明？声明已加？
- [ ] 紧急事件中是否避免了伪造实拍？（台风、地震、事故等）

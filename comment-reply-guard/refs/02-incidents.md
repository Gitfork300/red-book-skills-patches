# 评论与私信事故速查

| 现象 | 判据 | 处置 |
| --- | --- | --- |
| 合并评论清单后条目消失或误判未回复 | 不同来源的主键可能是 `id` 或 `note_id`；先统一键名再合并 | 按 ID 去重并对账来源总量，不用不可信的评论计数字段剪枝 |
| 二级评论未定位或被错挂到一级评论 | 折叠节点无法按 ID 定位；一级容器文本可能包含二级文本 | 先展开，再按确切评论 ID 定位；禁止文本兜底 |
| 回复后仍显示“未回复”，或系统提示被当作回复 | 子评论列表可能只含最新一条；关注提示不是我方消息 | 结合可靠通知 / 详情来源与消息发送方判定；以最后一条真实我方消息确认已回复 |
| 昵称规则导致误认我方身份 | 昵称可能变更，评论区与个人资料的旧称不一致 | 以评论接口确认的我方身份为准；不要把过时昵称作为唯一判据 |
| 私信被重复触达或超出处理窗口 | 时间字段为相对文本；系统插入的关注提示不是回复 | 先换算会话时间并应用当前 36 小时窗口；过滤机器人、主动广告与问卷 |
| 回复中出现站外导流或承诺提醒 | 外链属于高风险导流；“无法提醒”可能与现有提醒能力矛盾 | 采用当前批准话术；异常时停手并按风控规则排查，不复制历史反例 |

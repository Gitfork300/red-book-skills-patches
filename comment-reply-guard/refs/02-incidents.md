# comment-reply-guard / refs — 事故复盘与已确认事实

## 一、核对「是否已回复」的五个坑

1. **content-data 的「评论」字段不可信**：164 篇全显示 0，实际 14+ 篇有评论 → 不能用于剪枝。
2. **清单合并键名不一致**：`platform_notes_*.json` 用 `id`，`comments_all.json` 用 `note_id`；
   用 `x.get('id')` 合并会静默丢后者全部条目（实测漏 4 篇关键笔记 → 21 条评论误判）。**合并前先统一键名**。
3. **表情码写法不同**（`[偷笑R]` / `[doge]` 位置不一致）→ 匹配前先剥离 `\[[^\]]{1,12}\]` 与标点。
4. **排除我方自己的一级评论**：`nickname === '叻叻财'` 的一级评论要排除，否则混进自己发的 5 条。
5. **二级评论 DOM 定位坑**：默认折叠（`getElementById('comment-<二级cid>')` 取不到，报 `no_comment`）；
   展开后按 id 取才可靠；⚠️ **不要文本兜底**（一级容器 innerText 展开后含二级文本，会错挂到一级）——判据只能是 id。

## 四、站外链接实测与风险

2026-09-14 实测：回复里带 `https://xxx` **能正常发出且完整展示**（未被吞字/折叠）。
但这是明确高风险动作（站外导流，平台的敏感判定区）——读者省一步，账号可能被限流/限评/封功能。
要发就**控量 + 加间隔 + 盯异常**；出现异常先停，按 `xhs-risk-guard` 的"先排除我方问题"顺序排查。

## 五、私信处理口径细节

1. **默认只处理 3 天内**会话；「从未打过招呼的新朋友」放宽到 **5 天**；更早（9/6 及以前）一律跳过。
   时间字段是相对值（`刚刚` / `昨天` / `星期日` / `9月12日`），先换算再过滤。
2. **新朋友 = 默认打招呼表情包**。判据：会话摘要含 `我们已相互关注` / `你们已相互关注` / `关注了你`。
3. 已回复判据 = 消息区**最后一条是我方发的**；注意系统插入的"你们已相互关注😉"提示**不算我方回复**。
4. 官方机器人（薯条小助手等推广）、对方主动广告/问卷 → 不回。

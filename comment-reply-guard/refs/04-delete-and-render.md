# 删除链路与页面渲染坑

## 一、评论删除：DOM 只渲染前 N 条，深评论根本拿不到（2026-09-16 实测）

- **现象**：广告评论「拍摄需要吗」在 `get-feed-detail` 的评论列表里排**第 20 条**，
  但页面稳定只渲染 **17 条**一级评论 —— 无论怎么滚、怎么换容器，**DOM 里始终不存在该节点**，
  拿不到 `div.comment-delete-dropdown > svg.more`，删除无从下手。
- **试过且无效**（6 轮 4 个脚本，别再重复）：滚动加载、换滚动容器、
  `anchorCommentId` 深链、`pc_notifications` 通知页。**首次深链那次「成功」属渲染竞态，不可复现。**
- **判据（先做这一步再决定动不动手）**：
  先数 DOM 一级评论条数 vs API 返回的评论总数 ——
  **目标序号 > DOM 条数 → 直接判「不可删」，按铁律 16 / 17 报跳过**，不要开新一轮尝试。
- **结论**：页面渲染条数 < API 条数时，**删除能力只对前 N 条有效**，更深的评论只能 App 手动删。
- 关联铁律：16（不重试死磕、报跳过清单）、17（白天单项 ≤180s 且 ≤2 轮）。

## 二、「是否已回复」以接口为准，不信交接卡与旧报告（2026-09-16 实测）

- **现象**：深圳生命科学 919 那条评论，交接卡 §2.2 仍列它为「待回复」，
  但 `get-feed-detail` 实测 **`sub=1、我方二级=1`**（内容正是 `[A1] 官方公布的报名方式…`）→ **早已回复**。
- **教训**：报告与交接卡**会过时**（多轮会话、多轮脚本累积，写完就不再更新），
  **动笔前必须回查接口**（铁律 6 判据）；否则重复回复 = 刷屏 + 风控风险。
- **口诀**：**先查后回，不信旧账。** 只有接口说没回过，才算没回过。

## 三、删除入口与菜单文案（补 `refs/01`）

- 入口 `div.comment-delete-dropdown > svg.more`；菜单项实为 **「删除评论」**而非「删除」（须精确匹配）。
- React 组件 `el.click()` 无效 → 必须派发真实鼠标事件（见 `refs/01` 第八节）。
- 删除前**必须校验作者 + 内容全文**：港大案例里手写正文「闭门活动」≠ 实际正文「邀请制凭请柬」，
  校验拦下了误删（后按真实正文重删成功）—— **这道校验救过一次，不许省**。

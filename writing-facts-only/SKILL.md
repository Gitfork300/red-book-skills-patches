# writing-facts-only

> Patch：公开发布的内容**只陈述事实，不加评论、不提战略建议**。
> **体系：`publish`（发布体系）** —— 只适用于已发布的笔记（图文/视频）。
> ⚠️ 作用域边界：**不含评论与私信**（属 `comment-reply-guard`）。「只陈述事实」是两套体系共用底线，但篇幅/分段/标题规则不继承到回复。见 `SYSTEMS.md` X2。

## 写作规则

**允许**：已核实的客观事实、官方信源直接引述、标注来源、中性陈述语气。
**不允许**：价值判断、评价性形容词、建议、抒情收尾、互动引导话术、反问句（除非引用）、标题判断词（却/但/竟/竟致）。

## 硬约束

1. **事实核查**：量化数据双源核实；时效性内容查 7 日内信源；矛盾信源并列展示；查不到写"未查到公开数据"。
2. **应急/灾害双重禁令**：真实应急事件（台风/暴雨/地震/火灾等）禁 AI 生成"灾情实拍/现场感"；只许抽象示意 + 官方通报摘录；末尾标来源与发布时间。
3. **涉政/涉地图**：禁 AI 手绘国界/海岸线/行政区划、禁错绘漏绘台湾海南南海诸岛、禁政治符号；位置用文字描述。
4. **标题说明内容**：禁"流水号+日期"式命名；保留主体（哪场活动）+ 看点/门槛。
5. **参与方式写全**：邀约/专业观众/实名登记/审核/截止时间/入场凭证/名额限制；无门槛就直说"无需预约直接入场"。
6. **来源标注格式**：正文末尾 `信息来源：XX 官网/媒体，YYYY-MM-DD`（可省其一）；中文媒体用全名。
7. **展会/活动类底部评级块**（硬要求）：正文末尾必带「综合星级 + 四维 + 来源」，格式见 refs。

## 篇幅与分段（硬要求）

| 口径 | 范围 | 说明 |
|---|---|---|
| 核心正文 | **450–600 字** | 不含评级块/来源；**<450 信息不足**（2026-09-16 实测：字数跌到 342 时
观看时长与收藏率同步下滑），>600 必须删 |
| 全篇 | **< 1000 字** | 含评级块 + 来源 |

- **切分点 = 末个 `—` 分隔行**：`—` 之前算正文，`—` 及之后（评级块/来源/标签）算附加。
- 分段（扫读场景）：一段一信息点、每段 ≤3 行、首段 ≤2 行（什么活动+在哪+哪天）、关键信息独立成段、段间空一行、忌文字墙。
- 旧口径「正文 200–700（含评级块）」「核心正文 200–600」均已作废（2026-09-16 起下限提到 450）。

## 内容侧重与时长目标（2026-09-16 用户口径）

| 项 | 口径 |
|---|---|
| 内容侧重 | **实用导向**；但**技术内容每轮占比 ≥20%**（不足须补） |
| 技术稿写法 | 必须带「对普通职场人 / 普通人意味着什么」的**转译段**，不做纯术语堆砌 |
| 目标观看时长 | 展会类 **12–16s**、前沿类 **15–20s**；**<8s 为危险信号** |
| 骨架与肉 | **评级块是「骨架」，内容密度才是「肉」**——排版结构化保留，但不能替代信息量 |
| 35+ 人群 | 占比较高（官方画像 35+ 约 40%）可偏职场 / 兴趣 / 消费；⚠️ **不涉及父母、子女、防骗等敏感题材** |

依据（2026-09-16 官方数据 204 篇）：字数中位 640→342 与时长 19s→11s 同步腰斩，阅读速度无系统飙升；
控制选题后展会类时长 12–16s 收藏率 1.41%（最优），0–8s 仅 0.78%。

## 话题标签 `#`（硬要求）

- 每篇**必须带 3–5 个 `#话题标签`**：具体名词（`#云栖大会` 优于 `#AI`）、正文出现过的事实、`#` 后不留空格、标签间空格分隔。
- 🔴 **位置铁律：标签行必须是正文「最后一行」**——任何内容（**包括「来源：…」行**）都不能排在它后面。
  否则 `_extract_topic_tags_from_last_line()` 匹配不到 → 话题选择被静默整批跳过、`tagList` 为空（0915 批次 30 篇全踩过）。
  改法：**把「来源」行提到标签行之前**。
- **用前先验热度**：冷门标签不放。验证用 `search-feeds --keyword "云栖大会"`（看结果量/互动量）或看话题聚合页；结果个位数/无聚合/互动低 → 判冷门剔除。
- 标签不计入核心正文，但计入全篇 <1000 字。

## 标题标记规范（2026-09-16 新增）

- 标题**必须以 1 个方括号标记开头**：`[SSS]` / `[SS]` / `[S]` / `[A]` / `[P]` / `[X]` /
  `[天气]` / `[Canary]`，含义见 `start-daily-task` →「标题标记体系」
- **只能有 1 个**，优先级 `[Canary]` > `[天气]` > 等级；专题归属**不占标记位**，
  且标题不得使用序号（`①`、`（一）`、`系列1` 等），具体以 `safe-wording-guard` 为准。
- 标记占字宽（`[Canary]`=4.0、`[天气]`=3.0、`[SSS]`=2.5）→ 正文标题压到 **≤14 字宽**
  以保证总字宽 ≤18 余量线（平台硬限 20）
- 校验：`title_tag.py --check "<标题>"`（第 19 项预检）

# 05 · 封面规范（2026-09-12 升级）

> read_when: 生成 / 挑选 / 审核封面图时
> 本文件是 `MEMORY.md` 第 5 节的展开。**结论以主文件为准**。

## 风格

- ❌ **禁图标式几何剪影**（PIL 画戒指 / 手机 / 车 / 锁）—— 用户评「太简陋」
- ✅ 优先**摄影质感**：渐变 + 柔光斑 + 大字标题
- 复用 `_gen_ai_life_covers.py` 五件套

## 必需项（缺一不可）

| 项 | 要求 |
| --- | --- |
| 人物 | **无人物** |
| 地图 | **无地图与边界** |
| 水印 | **右下 AI 水印** |
| 尺寸 | **1024×1536** |

## 技术坑

- **渐变**：必须画 `1×H` 窄条再 `resize(BILINEAR)`，否则出现横向条纹
- `darken_top`：同理用 L 通道
- **标题换行**：用**显式行列表**，不要自动断行

## 紧急事件例外

台风等紧急事件改用**矢量示意图**，见 `08-weather.md`。


## 封面：官方宣传图 ≥80% —— **仅适用于展会 / 活动类**
（2026-09-16 用户原话；**2026-10-17 用户纠正口径**）

> ⚠️ **口径纠正（2026-10-17 用户拍板，别再算错）**：这条 ≥80% **只针对展会 / 活动类**
> ——即 E 组（展会·江浙沪）、F 组（展会·珠三角港澳），以及专题里的展会 / 活动篇。
> **A/B 专题、G/H 技术、Y Canary、W 天气不适用此门禁**：它们受「专题 KV 跨天禁复用 /
> 官方图常含人物或地图 / 国标文本无配图」约束，本来就凑不出足够官方图。
> 2026-10-17 曾把当日**全部 31 张混算**成 42%，属**口径错误**——真实展会口径当时是
> **3/10 = 30%**。算占比时**分母必须是「该批展会类封面数」，不是当日全部封面数**。

- 展会 / 活动类封面**先找官方宣传图**（主办方官网/组委会通稿/官方媒体配图/场馆展区官方图，去水印）
- 硬指标：`该批展会类官方图数 / 该批展会类封面数 ≥ 80%`；不足须补找官方图，**不得用字卡凑数**
- **执行脚本（2026-10-21 落地，B-085 裁定产物）**：`python _cover_official_ratio.py --date <MMDD> --strict`
  自动分「展会类判定 / 非展会类不判定」两组列账，`--strict` 时未达标 exit 1。
  兼容三种台账结构（`{"covers":[]}` / 扁平 list / 单条）。**巡检与收口必跑。**
  → B-085 已于 2026-10-21 15:40 由用户正式拍板「仅展会组 80%」，A/B/G/H/Y/W 不适用，**不再作风险登记**。
- ⚠️ **2026-10-17 用户新要求（逐篇，比批次数值更严）**：
  「**尽可能不要提供没有官方图的（展会）资讯**」
  → 逐篇把关：**拿不到官方图的展会稿，宁可不发**（撤稿 / 改选题），
  **不许用 AI 生图顶替**——生图只是临时占位，**不是合规交付**。
  → 实践口径（2026-10-17 F 组验证可行）：缺图稿**先撤出队列**去补官方图，补到才重新入队；
  补不到就放弃该篇。**不要为了凑篇数先发出去再说**——已发笔记换封面只能 App 手动编辑
  （见下方 SOP 第 6 条），脚本不可代改，发出去基本无法挽回。
- **封面文案 10–15 字**（2026-10-09 用户拍板）：表达正文核心、实事求是、专业口吻；
  禁口号式短语与「Canary · xx」类内部标记胶囊（tag_chip 已从生成脚本移除）；
  图源小字（`图源：xx 官方博客`）不算入 10–15 字
- PIL 摄影质感渐变字卡**退为兜底**，单批 ≤20%，并留痕图源与拿不到官方图的原因
  （此 ≤20% 是**单批总封面**口径；展会类的 ≥80% 官方图是**另一条独立门禁**，两条都要满足）
- 退路顺序：官方宣传图 → 真实感生图 → 渐变字卡 → 自然风光（确认版权）→ 抽象信息图
- 收尾报告须**分开列两组**：「**展会类**官方图 X/N（≥80% 达标？）」与「非展会类 Y/M（不适用门禁）」，
  兜底篇数及原因另计。**禁止把两组混成一个百分比报上来**（2026-10-17 就是这个误算）。

## 官方图来源金字塔 ·「挖不到」= 闭门会议（2026-10-17 用户拍板）

> **用户原话**：「做为有一定影响力的展会，一定有官方宣传信息的，不会什么都没有。
> 所以没有官方图片的，基本剩下**闭门会议**了。」

这条推翻了以往「官网没有就算了、退回生图」的做法。**是否构成「找不到官方图」，
必须先证明五层都真的挖过**——否则不是找不到，是没挖。

**来源金字塔（自上而下逐层挖，每层都要真的动手）**

| 层 | 来源 | 备注 |
|---|---|---|
| 1 | **主办方 / 组委会官网** | 不止首页！必翻新闻中心、往届回顾、展商服务、图库/下载、**banner 轮播位**、子页面（如 `about`） |
| 2 | **承办场馆官方网站** | 展馆常有「展会排期/场馆介绍/新闻动态」含官方实拍场馆图。**今日最大突破口** |
| 3 | **政府 / 园区 / 管委会官网** | 商务局、会展办、园区管委会的新闻稿配图 |
| 4 | **主办方 / 场馆官方公众号 / 官方通稿** | 自推文配图视同官方 |
| 5 | **权威媒体通稿配图** | 兜底层，须写明具体媒体与原文链接（e1017_03 上观新闻、e1017_05 温州新闻网均属此层并通过验收） |

**判定规则**
- 五层**逐层查过**仍一无所获 → 判定**疑似闭门 / 内部 / 未对外宣传活动** → **撤稿或改选题**，
  ❌ **绝不允许退回 AI 生图把它发出去**。
- 台账的 `fail_reason` 必须写清**每一层具体查了哪些站点/页面**，否则一律视为「没挖够」，不予采信。

**今日实证（三次「找不到」全部翻案）**

| key | 前次误判「找不到」的理由 | 实际在哪层挖到 |
|---|---|---|
| e1017_01 纳博会 | 官网只有 Logo + 含人物会场照 | 第 2 层：苏州国际博览中心官网场馆实景 |
| e1017_02 上海微波天线展 | 官网只有 Logo + 营业执照图 | 第 1 层：官网 `about` 子页上传目录里的 2026 官方 KV |
| e1017_04 杭州制冷冷链展 | 官网图库全是含人物观众照 | 第 1 层：首页 **banner 位**（不是图库页）里的场馆夜景 |
| f1017_05 广州车链展 | 官网只有 Logo 墙 + 含人物往届照 | 第 2/3 层：承办场馆 + 政府官网竣工新闻实拍 |

→ 结果：E 组 补到 **5/5**、F 组 **5/5**，展会类官方图由 30% 拉到 **100%**（新封面口径）。

### 补图只管未发队列，**已发布的一律不追溯**（2026-10-17 用户拍板）

> 用户原话：「**已发布的忽略。**」

- 发现某篇缺官方图，**先判它是否已发布**：
  - **已发布** → **直接忽略**，不再补救、不再进待办、不再追问用户；
  - **未发布** → 撤出队列 → 按金字塔逐层挖 → 挖到官方图才重新入队。
- 依据：脚本**无下架 / 编辑已发笔记封面的能力**（B-006），补图成果对已发笔记**物理上落不了地**，
  App 手动改属于纯人工投入，用户不为这项投入付费 —— 所以**不追溯就是既定口径**，不必每次重新请示。
- **报告口径分开写，不要混**：
  「**已发封面口径**」（实际发出去那张）与「**新封面口径**」（磁盘上现存的）。两者不同时并列给出，
  并注明差异来自哪几篇；不做「已达 100%」的单口径表述。

## 官方图落地 SOP + 台账硬闸门（2026-09-16 云栖批次实战）

> 完整细节在 patch `cover-image-rules` SKILL.md「官方宣传图获取 SOP」节（v1.6.0）。

1. **抓图**：官网 HTML 四类正则提图源 URL，按尺寸过滤（宽≥800 高≥400）；
   CDN 下载带 UA+Referer，大图超时加 `?x-oss-process=image/resize,w_1800` 重试。
2. **三查**（contact sheet 拼总览一次看完）：人物（清晰剪影/合影弃，模糊运动虚影可留）、
   年份（往届回顾旧 KV 弃，防事实误导）、地图/平面导览图/多栏文字图弃。
3. **竖版两模式**：`crop` 视觉图裁 2:3（横版取左侧避文字区）；`fit` 官方 KV **严禁竖裁切字**
   （APSARA→PSARA），完整缩放居中 + 模糊延伸背景。
4. **标注**：右下来源小字「图源：XX官方」；官方图**不加 AI 水印、不传 `--content-declaration`**。
5. **台账硬闸门**：每批写 `cover_sources_<批>.json`，发布前跑
   `check_cover_source.py --batch-dir <目录>`（预检第 10 项，退 0 才可排队）。
6. 首战记录：0916 A 批（云栖专题一）已发 5 篇字卡封面全部替换为官网官方图（5/5=100%），
   旧字卡备份 `_old_covers_0916/`；**已发笔记换封面只能 App 手动「编辑」**，脚本不可代改。

## 生成缺陷防线（2026-10-07 A 组封面事故后新增）

> 事故：`_gen_1006_a_covers.py` 产出的 `a1006_01`/`a1006_02` 两张封面因质量缺陷被人工删除，
> 一度被误判为「平台风控删笔记」（见 `_BUGS.md` B-019 / B-021）。

- **解释器**：封面脚本必须用
  `C:\Users\EricSupport(DMSH)\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（PIL 12.3.0）。
  skills venv 与 managed python **都不带 PIL**，会直接 `ModuleNotFoundError`。
- **标题只由 `add_common()` 出**：封面函数**禁止**再自绘同文案（如 `d.text(..., "CICAI 2026", ...)`），
  否则与 `add_common` 的标签重叠错位 —— 这就是 a1006_02 事故的根因。
- **发布前门禁**：`python xhs_publish/_check_cover_dup.py .` 须退出码 0
  （AST 检查「同一函数内自绘了公共绘制函数已负责的文案」）。
- **源图比例不可拉伸**：`band_from_src(box, w, h)` 的 `w/h` 必须等于 `box` 的纵横比。
  事故中 v1 把 `2400×413`(5.8:1) 拉到 `1024×960`(1.07:1)，**纵向拉伸约 5 倍**，圆 logo 变竖椭圆。
- **官方系统界面截图 ≠ 可用封面素材**：官网「欢迎使用XX会议系统 / 轻松报名 / 一站服务」
  这类**系统引导横幅**带营销引导语、且是界面截图，会被判「不美观 / 有风险」，**不得**当封面主图；
  确需从官方横幅取材时只取**右侧纯视觉区**，避开文字块。
- 重生成封面时用 `XHS_COVER_DIR` 环境变量把输出指到临时目录，
  **不要覆盖** `_archived_batches/` 下的归档证据。

## 构图硬标准（2026-10-12 用户拍板，替代「小卡片+模糊底」旧版）

> 事故：10-12 批次三版并存。最差版（c1012_05 已发，无法追改）= contain 小白边卡片，
> 清晰内容仅占 ~15%，大片模糊底 + 文案悬空。用户明令后续必须修正。

**竖图（源图宽高比 < 0.85，如 2:3、4:5）—— 默认构图：**
- **清晰内容铺满整幅 1024×1536**（cover 居中裁切），占比 100%
- **无白边卡片、无圆角框**（直接贴满）
- **文案压底部**：底部渐变压暗（0.48H 起，alpha→205）+ 白字黑描边（stroke 3）
- 参考实现：`xhs_publish/_mk_cover_1012.py` build() 竖图分支

**横图（≥0.85）—— 次选构图：**
- 放大到 **1.2W、高 auto**，居中裁左右（每边 ~8%），满宽贴入、无边框
- 过高才裁上下（上限 0.62H）；「卡片+文案」整体垂直居中
- 超宽 banner（3:1）无法铺满时**不得裁两侧 70%+**（会破坏 KV 完整），用 1.2W 即可

**其它硬规则：**
- ai_gen 兜底图底部小字必须写「AI 生成配图」，**禁标「官方主视觉」**（虚假标注）
- ai_gen 图 prompt 必须贴合具体展会/主题场景，**禁用通用概念图**（图文不符）
- 售票公告类官方图（含购票 CTA/bit.ly/二维码价格）**弃用**——封面不得带购票指引
- 断行：全串找分隔符（，,、与和的）取离中点最近者收前行尾；无分隔符才硬断

## 禁纯 LOGO 封面（2026-10-12 用户拍板）

> 事故：c1012_02（湾芯展）封面直接用官方 Logo 图，小放没信息量、铺满又难看（已发，无法追改）。

**取图优先级（从高到低）：**
1. 官方 **KV / 主视觉海报**（首选，天然竖版优先）
2. 官方**展馆外景 / 展区实景 / 往届现场照**（无人物）
3. 主办方通稿 / 官方媒体的**新闻配图**
4. **ai_gen 生图**（prompt 必须贴合该展会的具体场景，禁通用概念图）
5. **纯 Logo 图：尽量不用**——小放无信息量、铺满白底难看

**只有 Logo 时的处理（不是铺满）：**
- 把 Logo **贴在场景底图**上（官方场馆/展区实拍，或该主题的 ai_gen 场景图），Logo 占面积 ≤40%
- 封面文案照常压底部，主视觉仍是场景，Logo 只作身份标识
- 禁止：白底 Logo 居中铺满、Logo 拉伸变形

**找图动作**：先搜官网首页 banner / 主视觉下载页 / 展馆介绍页 / 往届回顾图库，
再搜主办方公众号与通稿；确认无人物、非地图、非售票公告（含购票 CTA 的弃用）。
- 横图 1.2W 满宽贴入时**必须边缘羽化**：`feather_mask(fw,fh, 0.11fw, 0.05fh, gamma=0.65)`
  左右 11%、上下 5% alpha 渐隐融合进模糊背景，消除硬切痕迹（2026-10-12 用户反馈「硬切不好看」）
- 封面文案断行**不得拆英文/数字 token**（Agentic/EPYC9006 整体移到行首/行尾）

## 封面唯一性：同批 + 同专题跨天禁止复用同一张源图（2026-10-14 违规事故）

**事故**：CICAI 2026（A 专题）与 IAB HK C26（B 专题）各自官网**只有 1 张主视觉**，
10-12 / 10-13 / 10-14 三天所有稿件都拿它当底图、只换封面文案；B 组同一天 4 篇还共用一张。
ahash 显示同专题相邻稿距离 **0~5**（阈值 12），平台判「封面连续相同 / 同一专题使用相同宣传物料」**违规**。

**规则（硬门禁）**
1. 任意两张封面（同批内 + 与历史各批）**ahash 距离 ≥ 12**；只换文案、底图相同仍算重复。
2. 发布前必跑：`python <patch>/cover-image-rules/helpers/check_cover_unique.py --date <MMDD>`
   （cwd = 稿件目录；退出码 1 = 有近重复，**禁止排队**）。与官方图 ≥80% 校验并列，两条都要过。
3. 「专题只有一张官方图」不是复用理由。扩源池顺序：
   ① 官网其它栏目图（议程 / 往届 / KV 变体 / 海报横竖版）
   ② **承办场馆或校区官方图库**（会议在哪个馆开就用哪个馆的官方实景）
   ③ 主办机构品牌视觉页（非纯 Logo）
   ④ 退回真实感生图 / 摄影质感字卡，台账如实标 `ai_gen`
4. 台账 `cover_sources_<批>.json` 加 `dedup` 字段（v1 / v2 整改），换下的旧图**外移**
   `xhs_publish/_archived/cover_dup_<MMDD>/`，不删。
5. 本次整改实例：A 组换浙大海宁国际校区官网场地实景 5 张（两两 39~110）；
   B 组换 HKCEC 官方图库 + KV 变体（两两 ≥51）；W 天气稿换 ImageGen 浓雾斜拉桥（vs w1013_01 距离 88）。

## 任何图禁二维码（2026-10-23 用户拍板，B-101）

> 用户原话：「**任何图 都不应该包含二维码**」——**不限官方图、官方海报、AI 生成图、字卡**。
> 事故：`f1023_02`（中德机器人论坛）封面直接用学会官网海报，海报主体是**微信二维码**，发布后被用户发现。

- **任何配图**下载/生成后必须过二维码检测（**可执行门禁，不要只靠目检**）：
  ```bash
  python <patch>/cover-image-rules/helpers/check_qr.py --file <各封面>
  ```
  退出码 `0` 通过 / `1` 确认含码（禁发）/ `2` 疑似含码（**必须人工目检裁决**）。
- 人工目检确认无码后登记白名单（按文件 md5 绑定，同名重生成自动失效）：
  ```bash
  python <patch>/cover-image-rules/helpers/check_qr.py --mark-ok <文件> --date <MMDD> --note "目检无码"
  ```
- 含二维码的图**一律禁用**：优先换**同源的干净裁选区**（避开码区），没有干净区就换图源；
  都没有 → 按「挖不到官方图」处理（撤稿/改题），**不得退回带码图凑数**。

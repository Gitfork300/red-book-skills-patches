# 08 · 恶劣天气复查自动化

> read_when: 跑天气简报、判断要不要发天气稿、做天气封面时
> 本文件是 `MEMORY.md` 第 8 节的展开。**结论以主文件为准**。

## 简报文件

- 路径：`weather/YYYY-MM-DD_weather_watch.md`
- 同日再跑 → **追加**「HH:MM 复查更新」章节，**不覆盖**

## 判定口径

两地任一区域满足以下之一 → 「有恶劣天气」→ **直接发布 1 篇**：

1. 有生效的气象灾害预警（**黄及以上**）
2. 被中央气象台**明示列入**大风 / 强降水影响区

都没有 → **只回报不发**。

### ⚠️ 不得加码（2026-09-15 用户澄清）

用户口径原话：「收到/即将收到严重影响就发 —— **那就是黄色及以上预警了**」。

判定只需满足上述两条之一，**不许自行叠加门槛**：

| ❌ 曾经的错误加码 | 为什么错 |
| --- | --- |
| "预警在非核心城市（如江门）不算" | 口径是**两地任一区域**，江门属珠三角九市，黄色就是黄色 |
| "过程已过峰值、是尾巴稿" | 过峰值≠无影响；有生效预警即发 |
| "没有新事件（台风未编号）不值得发" | 有生效预警本身就是充分条件，不依赖是否有新台风 |
| "当日已发 N 篇、密度太高" | 只受**间隔 ≥6 分钟**与**天气配额 ≤1/日**约束，不受当日总量约束 |

**自检顺序**：① 预警接口有没有两地黄及以上生效条目？→ 有就发。② 没有 → 再看是否被中央气象台明示列入影响区。③ 都没有 → 只回报不发。

### 🔴 兜底脚本只能正推、不能反否（2026-11-06，B-130）

`_weather_watch_1029.py` 是**粗筛兜底**，不是判据本身：

| 脚本输出 | 能否据以决策 |
|---|---|
| 有命中（当日 / 跨日候选） | ✅ 可据以发稿（仍按配额 ≤1/日） |
| `命中 0` | ❌ **不得**作为「今天不发 W 稿」的依据 → 以 08:00 automation 的语义判定 + 台风正式编号为准 |

- **判据是「生效中」，不是「当日发布」**。森林火险 / 干旱 / 寒潮 / 大雾 / 道路结冰 / 霾 这类可持续数日，
  跨日仍在生效**按命中计**；暴雨 / 雷电 / 大风 / 冰雹 / 高温 / 霜冻 / 沙尘 等短时类跨日视为失效。
- **区级发布算数**：核心城市的区县（花都/番禺/恩平/四会…）与市同级，标题写区名也命中。
- 教训：11-06 08:10 脚本按旧口径（只取当日发布 + 只翻 6 页）报「命中 0」，据此误报「今日无 W 稿」，
  而当日 08:18 实际已发花都森林火险黄稿 —— **automation 对、兜底错**，不能反过来。

## ⚠️ 只写「有影响的区域」（2026-09-17 用户口径）

用户原话：「这个天气指的是恶劣天气，**对指定区域无影响、无预警的后续不要写出来了**」。

天气稿是**恶劣天气稿**，不是天气科普／天气概览。写作范围：

| ✅ 要写 | ❌ 不要写 |
| --- | --- |
| 有生效预警（黄及以上）的区域 | 「XX 地生效预警为 0 条」 |
| 被中央气象台明示列入影响区的区域 | 无预警地区的常规天气（多云／阵雨／气温） |
| 未来 7～10 天会明显受影响（高温、台风、寒潮）的区域 | 「XX 地无影响」的对比段 |
| 台风路径及其明确影响的区域 | 非预警级的常规海区风力 |

- **不要为凑"两地对照"而写无影响区** —— 简报（内部文档）里必须回答两地是否有影响，但**对外稿件只写受影响的那一边**。
- 封面副标同理：不写「XX 无预警」。
- 若两地都无影响 → **不发稿**，只回报。

## 标题与查重（2026-09-17）

⚠️ `[天气] X日<地域>…` 与前一日同系列稿会构成 **5 字公共子串「天气+地域」** → dup_check rc=1。
**解法：地域换成上一级行政区（珠三角 → 广东）**，正文保留原地域全部细节。
实测：0917 初稿 `17日珠三角转晴热 周末35℃` 被拦 → 改 `17日广东转晴热 周末35℃` 后 rc=0（15/20 字宽）。

## 与会展类闸门的关系

- 天气类**不是**会展类 → `timeliness-window` 的地域 / 时效 / 资格三闸门**不适用**
  （预检 `exit=2` 属预期）
- 仍需过：dup_check / check_wording / 封面红线 / 天气配额 / 间隔
- **配额：天气类每日至多 1 篇；当日涉及红色 / 黑色预警时放宽至 3 篇**（用户 2026-09-15）
  - 跑 `quota_check.py --kind weather --level 红`（或 `黑/黑色/black/red`）→ 上限 3
  - **不传 `--level`（或传蓝/黄/橙）→ 上限仍是 1**；不确定就按 1 篇算
  - `--kind typhoon` 是 `weather` 的别名，同一配额池

## ⚠️ 打包一篇 · 不写「无重大影响」的天气（2026-09-17 用户订正）

用户原话：「天气内容不要合并发送，只需要把当前的恶劣影响发出来就好。昨天的已经没有意义了」。
**我第一次理解偏了**（以为要一篇一事件）；用户随后纠正：

> 「恶劣天气打包写在一个文章中，只是不要有【无重大影响】的天气描述。」

**正确口径 = 判据是「有没有重大影响」，不是「是不是同一个事件」**：

- **打包，不拆分**：当天有若干互不相关的恶劣天气（大雾 + 高温、暴雨 + 雷暴大风…）→ **全部写进同一篇**。一天仍只发 1 篇。
- **不写无重大影响的天气**：无预警区的常规天气、普通逐日预报、常规非预警级风力、已被官方明示无影响的事件 —— 一律不写。

| 要写（全部打包进同一篇） | 不要写 |
| --- | --- |
| 当前全部生效中的恶劣天气预警（黄及以上） | 「XX 地生效预警为 0 条」「XX 无影响」 |
| 即将发生、会影响出行/航班航运的恶劣影响 | 无预警区的常规天气（多云/阵雨/气温） |
| 上述影响的预报走向 | 普通逐日天气预报整段罗列（「广州市区 17—18 日多云 24～34℃…」） |
| — | 非预警级的常规海区风力 |
| — | 已被官方明示无影响的事件（中央气象台称对我国近海无影响的台风） |
| — | 昨天及更早的过程回述（「本轮降水收尾」这类过渡句） |

- 与「只写受影响区域」（见上节）叠加：先筛**区域**（只写受影响的一边），再筛**内容**（只写有重大影响的），**全部合进一篇**。

### 故障补检（不再等第二天）

| 场景 | 动作 |
| --- | --- |
| 发布失败（脚本报错 / 无 note_id / verify-note found=false） | 修掉原因 → **重新检索一轮**（确认事实仍成立）→ 重发；每轮最多重试 2 次，再失败就写简报 + present_files 回报 |
| 笔记被删除 / 审核不通过（用户告知，或 verify-note true→false） | 视为**未生效**，重新检索复查（事实 + 配额口径重判）→ 重发；重发前必跑 dup_check / check_wording，**标题换结构**错开查重 |
| 登录态失效 / 平台限制当天修不好 | 用 automation_update（once，约 60 分钟后）挂一次性补跑，提示语沿用主 prompt |

- 触发补检时，简报里要标注是「例行每日检索」还是「故障补检」，并写清触发原因。
- ⚠️ **配额口径**：发布失败／被删除的那一篇，在当日配额判断里**不计入** 3 篇额度，但条目仍在 publish_log.json 里，回报时须单独列出说明。

## ⚠️ 不得跨日顺延（2026-10-07 用户拍板，结案 P-008）

用户原话：「**天气类文章不能跨日，如果错过了，就重新检测当天天气情况。**」

- **当天没发出去 = 作废**：不得顺延到次日补发；顺延稿**不占次日配额**（次日照常有 1 篇天气额度）。
- **次日动作 = 重检，不是重发**：重新跑 `weather/_fetch_weather.py <当天>`，**按当天事实**重新判定、重新建仓；不复用昨日结论，不复用昨日稿件。
- 触发场景：卡在 **23:00–01:00 禁发窗口**（铁律 3b）没发出 → 该稿直接作废，**不要**留到次日 01:00 补发。
- **反面教材**：`w1006_01`（10-06 建仓、卡窗口到 10-07 01:00 才发）——既违反本规则，又让 10-07 当天新触发的事实（广东森林火险 32 条）无处可发。
- **副作用与解法**：顺延稿与次日稿题材天然撞车（本次 `dup_check` 因与 `w1006_01` 共用「森林火险预警」6 字被拦 rc=1）→ 按上文「标题与查重」换结构错开（本次定稿 `[天气]广东11市森林火险`，rc=0）。
- **查证口径**：判定「今天天气稿发过没有」只认**当天建仓并当天发出**的稿件；顺延稿一律不计。

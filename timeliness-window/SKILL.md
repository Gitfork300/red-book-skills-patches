# 时效窗口 + 可发布资格

> 会展活动类选题的**三道闸门**：时效、资格、地域（+ 恶劣天气配额）。
> 用户 2026-09-11/14 多次裁定，硬规则以本文件表格为准。

## 一、时效窗口（硬规则）

以**发布当天**为基准日 `D`。

| 类别 | 窗口 | 适用 |
|---|---|---|
| 普通单篇 | `[D, D+7]` | 单篇活动稿 |
| 专题系列 | `[D, D+15]` | 同一事件的系列预热连载（三条件：同一事件 / 预热连载 / 用户指定或按系列策划） |

**只有两个合法入口**（没有"登记已开放"这一条）：

1. **近 7 天开始入场** —— 开幕日落进 `[D, D+7]`
2. **近 7 天内必须开始报名** —— 报名**开始日**或**截止日**落进 `[D, D+7]`

**「免费登记 / 开放登记 / 可预登记」一律不构成豁免**（2026-09-14 明令）——只够作正文提示语，不算"现在必须决定"。

| 类型 | 判定 | 结论 |
|---|---|---|
| A 正在举行 | 开幕日 ≤ D ≤ 闭幕日 | 可发 |
| B 即将开幕 | D < 开幕日 ≤ D+7 | 可发 |
| C 报名节点在窗内 | D ≤ 报名开始/截止日 ≤ D+7 | 可发 |
| 太早 | 开幕日 > 窗口上限 且无窗内报名节点 | 不写不发，进待发池 |
| 已过期 | 已闭幕 / 报名截止 < D | 丢弃 |
| 仅"登记已开放" | 开幕日 > 窗口上限，登记开但无窗内报名节点 | **不写不发** |

**边界**：开幕日远但报名截止近（如 10/12 开幕、9/14 截止）→ 按 C 判合格，正文突出报名截止；报名截止多口径 → 取最早；`D+7`（专题 `D+15`）当天算窗内。

## 一之二、专题连续性（专题不停更 · 硬规则）

> 用户 2026-09-17 原话：「专题内容比较丰富，不要每天都换专题，一个专题至少等展会结束后T+2再换其他的」
> 用户 2026-09-18 原话：「专题活动没结束，文章就不要停。停止时间可以限定为结束后T+2」「云栖大会不要断，请继续，补上」

| 专题状态（D=发布当天） | 执行口径 |
|---|---|
| 展会未闭幕 | **每日持续更新该专题，不得断更、不得中途换专题** |
| 已闭幕、未过 T+2 | 仍属该专题窗口，不得切换 |
| 已过闭幕日 T+2 | 专题停止，可切换下一专题 |

- 「专题」指正在连载的同一事件系列（认定三条件见上节专题系列口径）。
- 断更过的专题只要展会未闭幕，**须立即恢复并补上**（2026-09-18 用户对云栖大会的明确要求）。
- 当前执行：**云栖大会**（2026-09-22~24，杭州国际博览中心）专题最后一批发于 **2026-09-16 20:41**，09-17/09-18 中断 2 天，即日起恢复补上，持续更新至 **2026-09-26**（闭幕 9/24 + T+2）后才可切换。

## 二、可发布资格（硬规则）

动笔前必须核实：**是否有直播**、**普通观众能否自行报名**。

| 有直播 | 普通观众可报名 | 结论 | 文案要求 |
|---|---|---|---|
| ✅ 有 | 任意 | 可发 | 写明直播平台、时间、是否需预约 |
| ❌ 无 | ✅ 能 | 可发 | 写明报名方式与门槛 |
| ❌ 无 | 邀请制 | **可发**（2026-09-14 解禁） | 只写已公开成果与案例 + **必须注明邀请制** |
| ❌ 无 | ❌ 不能（非邀请制闭门） | 不得发布 | — |
| 未核实 | 未核实 | 不得发布 | 先查清 |

**邀请制三条硬要求**（缺一不可）：① 只写已公开成果与案例（可溯源，不写报名引导、不预测）；② 正文明确注明邀请制；③ 成果案例仍须 ≥2 源交叉验证。判定走 `--public-signup invited`。
「邀请制」≠「闭门会」：有明确主办方、有公开产出的可发；查不到主办方的闭门会仍不发。付费但公开可报 → 算"能"，须写明付费。

## 三、地域范围（会展活动类硬约束）

会展活动类（展会/论坛/峰会/嘉年华/科普展等有举办地选题）**只发江浙沪或珠三角**，其他地区一律不写不发：

| 区域 | 覆盖 |
|---|---|
| 江浙沪 | 上海全域；江苏（南京、苏州、无锡、常州、南通、扬州、镇江、泰州、盐城、徐州、淮安、连云港、宿迁等）；浙江（杭州、宁波、温州、嘉兴、湖州、绍兴、金华、衢州、舟山、台州、丽水等） |
| 珠三角 | 广州、深圳、佛山、东莞、珠海、中山、惠州、江门、肇庆；含南沙/前海/横琴/大湾区（港澳写"中国香港/中国澳门"） |

只约束"会展活动"类；研究成果/政策解读类不受限。多地巡回有任一站落在范围内即可发（正文写清哪一站）。判定走 `geo_check.py`（退出码 0 合格 / 1 不合格 / 2 无法识别按不合格）。

## 四、选题配额（每日上限）

恶劣天气类（含台风影响，全部灾害类型 +「预警」合并计数）：

| 预警级别 | 每日上限 |
|---|---|
| 红 / 黑 | **3 篇** |
| 蓝 / 黄 / 橙 / 未指定 | **1 篇** |

配额跨篇约束，当天达上限即使其它全过也不发；不确定级别一律按 1 篇（从严）；超配额压次日或进待发池。判定走 `quota_check.py --kind weather [--level 红]`（`--kind typhoon` 是别名；不传 `--level` 按 1 篇）。

## 五、预检脚本

```bash
check_window.py --start 2026-09-15 [--end ...] [--deadline 2026-09-14] \
  --live no --public-signup yes|no|unknown|invited [--category normal|series] [--json]
geo_check.py --city 杭州   # 或 --text "<全文>"
quota_check.py --kind weather [--level 红]
```

退出码：`check_window` 0 可发 / 1 时效不合格 / 2 参数错误 / 3 资格不合格；`geo_check` 0/1/2；`quota_check` 0 未满 / 1 已满 / 2 参数错误。

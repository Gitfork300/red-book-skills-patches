# 时效窗口 + 可发布资格

## 为什么有这条

小红书的活动类笔记吃的是"现在能去 / 现在要决定"的即时价值。
提前一两个月发布，读者看完既去不了也不用报名，等到真临近时早被刷走——
**内容没有失效，但已经没有及时性**，等于白写。

还有一类内容，就算时间刚好也不该发：**读者根本参与不了**。
闭门会议、仅限特定从业者的专业研讨，普通读者既去不了现场、也没有直播可看，
发出去只能干看着。用户明确要求这类不发。

用户原话（2026-09-11）：
> 后续请仅关注近 7 天正在举行的，以及近 7 天需要提前报名的展会。
> 不要提前很久发布，这样会让内容不具有及时性。

用户原话（2026-09-11，第二轮）：
> 请注意后续展会内容，如果有直播请提示，如果没有直播且普通观众无法报名，那就不要发布。

## 一、时效窗口（硬规则）

以**发布当天**为基准日 `D`，窗口 = `[D, D+7]`。

### 合格（可发布）

| 类型 | 判定 | 例子（D = 2026-09-11） |
|---|---|---|
| **A 正在举行** | 开幕日 ≤ D ≤ 闭幕日 | 外滩大会 9/9—9/12 → 还剩 1 天 |
| **B 即将开幕** | D < 开幕日 ≤ D+7 | 某展 9/16 开幕 → 5 天后 |
| **C 报名窗口内** | D ≤ 报名截止日 ≤ D+7 | 报名 9/14 截止 → 还剩 3 天 |

满足任一即可。

### 不合格（禁止发布）

| 类型 | 判定 | 处理 |
|---|---|---|
| **太早** | 开幕日 > D+7，且（无报名截止 或 截止日 > D+7） | 不写不发；记进待发池，到窗口再写 |
| **已过期** | 已闭幕，或报名截止日 < D | 直接丢弃 |

### 边界处理

- **开幕日远、但报名截止近**（如 10/12 开幕、9/14 截止报名）→ **按 C 判合格**，因为"现在必须决定"。正文要突出报名截止，而不是开幕日。
- **报名截止日有多个口径**（官网 10/9、渠道写 9/20）→ 取**最早**那个做窗口判断，正文中如实列出差异。
- **常年展/无固定截止** → 不属于本规则约束，但发布时须写明展期。
- **D+7 当天算窗内**（闭区间）。

## 二、可发布资格（硬规则）

时效过了只是"什么时候发"的问题，资格要回答"这条到底该不该发"。
**展会/活动类选题，动笔前必须核实两件事**：

1. **是否有线上直播**（可在线观看）
2. **普通观众能否自行报名参与**

判定表：

| 有直播 | 普通观众可报名 | 结论 | 文案要求 |
|---|---|---|---|
| ✅ 有 | 任意 | **可发** | **必须写明直播信息**：观看平台、直播时间、是否需预约；有回放也注明 |
| ❌ 无 | ✅ 能 | **可发** | 写明报名方式与门槛 |
| ❌ 无 | ❌ 不能 | **不得发布** | 读者既去不了也看不了（如闭门会、仅限邀约、仅限特定从业者） |
| 未核实 | 未核实 | **不得发布** | 先把两项查清；不确定一律按不可发布处理 |

补充约定：

- **"能报名"要区分门槛高低**：仅限邀约 / 仅限某类机构从业者 / 需单位推荐 → 视为"不能"，不得发布。
- **付费但公开可报** → 算"能"，可发，但正文须写明是付费活动；不要写成免费。
- **直播信息不明确时**（如"计划直播"未定档）→ 不写"有直播"，按未核实处理，或等主办方公布后再发。
- **政策类 / 攻略类内容不适用本节**，只看时效与否（多数政策类也不受 7 天窗口约束，另按各自规则）。

## 三、地域范围（会展活动类硬约束）

> 用户 2026-09-11 要求：
> 会展活动，必须是**江浙沪或者珠三角**，其他地方不用管。

会展活动类选题，只有落在下列区域才可发布；**其他地区一律不写不发**（不是"排后面"，是直接排除）。

| 区域 | 覆盖 |
|---|---|
| **江浙沪** | 上海全域；江苏（南京、苏州、无锡、常州、南通、扬州、镇江、泰州、盐城、徐州、淮安、连云港、宿迁、江阴、昆山等）；浙江（杭州、宁波、温州、嘉兴、湖州、绍兴、金华、衢州、舟山、台州、丽水、义乌等） |
| **珠三角** | 广州、深圳、佛山、东莞、珠海、中山、惠州、江门、肇庆；另含南沙、前海、横琴、粤港澳大湾区（港澳一律写"中国香港／中国澳门"） |

规则细节：

- **只约束"会展活动"类**（展会 / 论坛 / 峰会 / 嘉年华 / 科普展等有举办地的选题）；已公开研究成果、政策解读类**不受地域限制**。
- 活动带"多地巡回"时，只要有**一站**落在江浙沪/珠三角即可发，但正文必须写清是哪一站。
- 线上为主、无线下举办地的活动（纯线上发布会等）→ 视为不受地域约束，但仍要过时效与资格。
- 判定一律走脚本，不靠印象：

```bash
python <patch>/helpers/geo_check.py --city 杭州      # 退出码 0 合格 / 1 不合格 / 2 参数错误
python <patch>/helpers/geo_check.py --text "<稿件全文>"
python <patch>/helpers/geo_check.py --list
```

退出码：`0` = 在允许范围 / `1` = 不在允许范围（不得发布）/ `2` = 参数错误或未能识别（按不合格处理，需人工确认）

## 四、选题配额（每日上限）

> 用户 2026-09-11 要求：**每天至多发布一篇关于台风的影响**（如有）。

高频、易刷屏的选题要限篇数。当前硬配额：

| 选题类别 | 配额 | 计法 |
| --- | --- | --- |
| **台风影响类**（含热带低压 / 热带风暴 / 强热带风暴 / 热带扰动 / 南海扰动 / 风暴潮） | **每自然日至多 1 篇** | 按发布日志 `publish_log.json` 里的**发布时间所在日期**统计 |

规则细节：

- 配额是**跨篇约束**：当天已发过 1 篇台风，第二篇即使时效、资格、用词、字数、封面全过，也**不得发**
- 超配额的稿件**压到次日**或登记进待发池，不要硬发
- 台风预警与台风影响**合并计数**（"预警"本身也是台风影响内容），不拆成两类各发一篇
- 以本地时间的自然日为准（00:00–24:00）
- 判定一律走脚本，不靠印象：

```bash
python <patch>/helpers/quota_check.py --kind typhoon            # 查今天
python <patch>/helpers/quota_check.py --kind typhoon --date 2026-09-11
python <patch>/helpers/quota_check.py --kind typhoon --json
```

退出码：`0` = 配额未满可发 / `1` = 配额已满不得再发 / `2` = 参数错误

## 五、预检脚本

```bash
# 地域范围（活动类必跑）
python ~/.workbuddy/skills/red-book-skills-patches/timeliness-window/helpers/geo_check.py \
  --city 杭州
python ~/.workbuddy/skills/red-book-skills-patches/timeliness-window/helpers/geo_check.py \
  --text "$(cat content.txt)"

python ~/.workbuddy/skills/red-book-skills-patches/timeliness-window/helpers/check_window.py \
  --start 2026-09-15 --end 2026-09-15     # 展期（至少给 --start 或 --deadline 之一）
  --deadline 2026-09-14                    # 报名截止（可选）
  --live no --public-signup yes            # 资格：是否有直播 / 普通观众能否报名
  [--today 2026-09-11] [--window 7] [--json]
```

- `--live` / `--public-signup` 取值：`yes` / `no` / `unknown`（展会/活动类必填）
- 退出码：`0` = 可发布 / `1` = 时效不合格 / `2` = 参数错误 / `3` = 资格不合格
- 只做时效判定时可不传资格参数，行为与 v1.0 一致
- 判定值：时效 `ONGOING` / `OPENING_SOON` / `DEADLINE_SOON` / `TOO_EARLY` / `EXPIRED`；
  资格 `ELIGIBLE_LIVE` / `ELIGIBLE_SIGNUP` / `NOT_ELIGIBLE` / `UNKNOWN`
- `--json` 便于脚本串联；`--today` 用于回溯测试

典型调用：

```bash
# 闭门会议：无直播 + 不对公众 → 退出码 3，不发
check_window.py --start 2026-09-12 --live no --public-signup no

# 有直播的行业论坛 → 退出码 0，文案须写直播信息
check_window.py --start 2026-09-18 --live yes --public-signup no
```

## 与其他 patch 的关系

- 在 **`safe-wording-guard`（15）** 之后、**`publish-preflight-guard`（25）** 之前执行：先查词，再查时效与资格，最后总检查
- **`publish-preflight-guard`** 的总检查表第 2 项已挂上本条
- 与 **`writing-facts-only`（30）** 配套：时效/资格是"该不该发"，facts-only 是"发什么内容"
- 直播提示的写法参照 **`writing-facts-only`**：只写平台、时间、是否需预约这些事实，不加评价

## 待发池（避免漏掉远期活动）

提前很久的活动不是丢弃，而是**登记后等窗口**。
在 `state/pending_pool.json` 记录：`{活动名, 开幕日, 报名截止日, 来源, 登记日期, 可发布起始日}`。
到期由 agent 或自动化任务捞出重走检索—写稿—预检流程（**信息可能已变，必须重新检索核实**，不能直接发旧稿）。
因资格不合格被拦下的，也一并登记并在 `remark` 写明原因，便于日后复查是否新增直播或放开报名。

# publish-loop-guard / refs — 实现细节与事故

## 一、查重实现细节（`dup_check.py`）

**事件标识**：以 论坛/大会/峰会/展/博览会/年会… 结尾的专名一致 → 高置信重复。
`--title` 模式同时启用「公共子串 ≥5 字」信号；日期串（`9月11日`）与数字串不作证据。

**模板串不作证据**：第 2 道信号在 `identity()` 上算 —— 先剥掉日期（`16日`/`9月`/`第3届`）与模板动词（`开幕`/`举办`/`举行`/`同期`…），只让事件名本体参与 LCS。否则 `苏州AI算力展16日开幕` 与 `深圳低空经济展16日开幕` 会因公共子串「展16日开幕」误判重复。

**稿件同名 = 自己不算重复**：排队前预检时标题通常已落盘到 `xhs_publish/`，若把稿件文件算进来每条都撞自己。⚠️ 但**日志同名必须保留**（= 已发过要拦）→ 预检必须在发布前做。

全量巡检 `dup_check.py`（严格，误报极低）；`--loose` 会多看出一批同事件系列稿。

## 二、漏发复核的实现坑

### `list_all_notes.py`（合规审计全量清单）

1. **必须复用主脚本 `XiaohongshuPublisher`**，不要自搓 CDP WebSocket。自搓版把 `Network.enable` 参数写成 `maxPostSize`（正确名 **`maxPostDataSize`**）→ 网络域没启用、一个事件收不到，现象是"页面渲染正常但接口完全没发请求"，极易误判成风控。
2. **接口不能直接 `fetch`**：`GET /api/galaxy/v2/creator/note/user/posted?tab=0&page=N` 需页面自生成签名头，直调返回 406。只能滚页面、从 CDP 网络响应里收。
3. **滚内容容器不是 window**：笔记列表在可滚 `div` 里。
4. **页签是本地过滤**：切页签不重发请求 → 只看 tab=0，状态从 `tab_status` 读：`1`=已发布 / `0,2`=审核中 / `3,-1`=未通过。
5. **登录态缓存不可信**：`check-login` 命中 `tmp/login_status_cache.json`（TTL 12h）可能报"已登录"实已失效，先删缓存再跑。

### 长批次硬停止时间

把截止时间写进队列脚本（不靠 agent 记时间）：

```python
DEADLINE_TS = time.mktime(time.strptime("2026-09-11 07:50", "%Y-%m-%d %H:%M"))
```

判定点放在**间隔等待之后、真正提交之前**，否则等待 8~12 分钟期间到点还会多发一篇。

## 三、读正文（`read_note_body.py`）与风控限流

路径：`https://www.xiaohongshu.com/explore/<id>?xsec_token=<tok>&xsec_source=pc_user`（裸链撞登录墙，必须带 token）。

⚠️ **风控限流（最关键）**：连续访问约 30 个公开页后，后续请求一律重定向登录页（`ok=false`）——**这不是登录失效，是限流**（2026-09-12 实测：前 27 篇读到 24，紧接着 28–54 全被挡）。

守卫已内建（规则权威在 `xhs-risk-guard`）：
- 单次会话 ≤25 篇（`--limit` 填更大也会被夹并告警）；
- 连续 3 篇 `ok=false` 立即熔断，剩余标 `skipped`、当场停手；
- 熔断后 4 小时冷却，冷却期内再跑退 3、不碰 Chrome；
- 先用 `list_all_notes.py --wording` 零成本扫标题，只对可疑篇目读正文。

开批前确认：`xhs-risk-guard/helpers/risk_state.py check --kind read-body`（退 0=可跑 / 3=冷却中）。

桌面端读正文的其它路径已确认全死：列表接口无正文字段、无编辑/预览入口、`note-manager/detail` 404、编辑页不回填、页面内直调 feed 406/500。**公开页 + token 是唯一可行路径。**

## 四、查重第三道信号（地点 + 日期）—— 2026-09-16 事故与设计

### 事故

用户当日指令第 3 条：「**后续尽可能避免重复标题**」。查证时发现三篇 Canary 第二轮稿件里
**两篇与已发稿是同一活动**（改标题措辞绕过了闸门）。
⚠️ **口径已修正（2026-09-17）**：`[Canary]` 是实验性标记，**不在「不得重复」范围内**，
「同一活动换标题重发」**不算违规、不追责、不下架**。本第三道信号对 `[Canary]` 稿**豁免**，
只保留「标题逐字不相同」这一条底线。下表保留作**信号设计的历史溯源**，不再作为追责依据：

| 稿 | 标题 | 撞上的已发篇 | 原判 |
|---|---|---|---|
| c6 | `[Canary] 香港医疗AI论坛922 报名` | 9/15 `香港具身智能医疗论坛 9月22` | 预检 **PASS** ✗ |
| c7 | `[Canary] ASSIST2026 报名与议程` | 9/16 12:53 `[S] 上科大AI研讨会918开幕` | 预检 **PASS** ✗ |
| c5 | `[Canary] 佛山AI青年论坛919 报名方式` | **9/13** `佛山大湾区AI青年论坛 免费` | 预检 FAIL ✓ |

根因：原两道信号都拦不住「换措辞的同活动」——
- **事件标识**要求专名**完全相等**：「香港医疗AI论坛」≠「香港具身智能医疗论坛」；
- **公共子串**阈值 5 字：`identity()` 剥掉日期后两篇只剩「医疗」「论坛」各 2 字 → 不够。

c5 之所以被拦，是因为它撞上了平台快照条目，偶然撞出 6 字公共子串「AI青年论坛」。

### 设计

同一场活动绕不过「举办地 + 举办日期」，故补第三道信号：

```python
shared_d = dates(t1) & dates(t2)      # 会期交集（922 / 9月22 / 9-22 已归一为 0922）
shared_p = places(t1) & places(t2)    # 城市交集
# 剥掉 地名 + 日期 + 事件后缀(SUFFIXES) + 通用词(NOISE_WORDS) 后仍 ≥2 字公共词 → 判重复
```

- **日期归一**：`(\d{1,2})月(\d{1,2})` → `MMDD`；`(\d{1,2})[-/.](\d{1,2})` → `MMDD`；
  3~4 位数字（排除 `20xx` 年份）→ `MMDD`；只有「日」无「月」→ `Dnn` 占位。
- **只挂宽松模式**（= 单条预检「拦住一篇要发的稿子」）；全量扫描不加，避免历史数据刷屏。
- **系列稿（`--series`）不豁免**：`--series` 只放宽「活动名公共子串」，第三道信号照常生效。
- ⚠️ **`[Canary]` 稿豁免本信号（用户 2026-09-17 定稿）**：实验性标记不在查重范围，
  **允许复用已发过的同一活动**，只保留「标题不相同」底线。执行时 `[Canary]` 稿跳过第三道信号。

## 防重复发布（2026-09-17 事故，v1.8.1）

**现象**：A 组 5 篇跑完，平台上 ②③④ 各有**两条**（note_id 十六进制相邻、相隔 2~16 秒），
发布链日志却显示每篇只发一次、且 a5 判 FAIL。

**根因**：`publish_one` 里 `for attempt in range(1, 4)` 的重试，判定只看
`"PUBLISH_STATUS: PUBLISHED" in out`。`publish_pipeline.py` 超时（600s）被 kill 时
stdout 丢失 → 判定"没成功" → 重试 → **平台上多一条**。首篇实际已发布成功。

**修复（已应用到 _publish_chain_*.py）**：重试前先 `verify_note(title)`，
平台上已存在同名笔记就判定已发、立即停止重试：

    pub_ok = "PUBLISH_STATUS: PUBLISHED" in out
    if pub_ok: break
    _vf, _vs, _vr, _vsum = verify_note(title)
    if _vf:
        print("平台上已存在同名笔记 -> 判定已发，停止重试")
        pub_ok = True
        break

**判断标准**：发布链报 FAIL 不等于没发。**以平台为准，不看日志**。
批次结束后用 `recent_published.py --days 1` 或抓个人主页快照核对条数。
